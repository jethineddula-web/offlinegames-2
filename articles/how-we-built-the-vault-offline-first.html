How we built the vault to work offline-first

The vault looks simple — a grid of covers — but offline-first on the web is three caches fighting you. We learned that when phones kept showing old games after we deployed new ones. Incognito was fine. Regular Chrome was stale. This is the fix we shipped in sw.js og-v7 and og-v8, plus _headers, and why catalog.js is now 18KB not 510KB.

Problem 1: base64 covers in catalog.js

Early vault embedded 13 covers as base64 data URIs inside SITE_GAMES array. File was 510KB, parsed as JS on every load. First load on mid-range Android: 1.8 seconds just to parse. We moved covers to real files under /covers/ — JPEGs and SVGs, ~12KB each. Catalog is now 18KB with 21 news posts. Loads in 90ms. News images that are still SVG use data URIs intentionally small, but game covers are real files.

It also made the first load noticeably faster, which matters most on an old phone. See best games for short sessions for how small some of these games are — Pop-a-Lock is 40 KB, 2048 is 80 KB.

Problem 2: cache-first service worker

og-v3 served everything under /games/ and /covers/ cache-first. Once file in SW cache, never re-fetched. So when we fixed a bug in Chess 3D, phones kept old bug. Fixed in og-v5 to network-first — but network-first as plain fetch(req) is a lie.

Problem 3: browser HTTP disk cache

This took weeks. fetch() consults browser's own HTTP disk cache before network. _headers was stamping /games/* with max-age=604800 and /covers/* with immutable, max-age=2592000. So fetch() returned week-old (or month-old immutable) copy from disk, SW dutifully refreshed its cache with stale bytes. Incognito had no disk cache, so looked correct. Regular profile was poisoned.

Fix in og-v7: netFetch() forces cache: "no-cache". Code:

function netFetch(req){ try{ return fetch(new Request(req,{cache:"no-cache"})); } catch(e){ return fetch(req); } }

That tells browser: do not serve from HTTP disk cache without asking server. Server may answer 304 Not Modified, so cheap — revalidation, not full re-download. That plus _headers fix to max-age=0, must-revalidate for /games/* and /covers/* means online phone always sees server version, offline still works because cache is fallback.

og-v8 bump now invalidates old caches outright — caches.keys() delete if version not current. So phones carrying stale games start clean moment og-v10 activates.

What offline actually means

We mean two practical things: no app store, and after first load, logic lives in page. You still need connection first time to get HTML, CSS, game files. After that, service worker serves from cache if offline. High scores in localStorage, not server. See what offline actually means for honest limits — we don't promise miracle console.

Why same-domain matters: most free game sites are iframes to other portals. If portal goes down or injects pop-up, game breaks. We host everything on offlinegames.art so offline works. Only external calls are AdSense and Google Fonts, async non-blocking. If they fail, game still runs. For trust argument, see why no-download matters.

Viewport split and shape bug

Pinch-to-zoom should never be disabled on a page of text. We had a script locking the viewport site-wide, including on About, Privacy and the guides, which made them awkward for anyone who needs to enlarge type. It now applies only to the game overlay, where a two-finger swipe would otherwise zoom the page in the middle of a level. Everything you read on the site can be zoomed normally.

That is why guides.html now shows 14 cards clean, no duplicate header, and news.html shows editorial intro not placeholder.

How we test before zip

Every release follows the same route: regenerate the per-game pages and the sitemap, raise the service worker version so phones know to fetch a fresh list, then check that the written pages still zoom and the sitemap is valid before anything ships. See News for dated entries — September adds 8 games: Arrows Puzzle, Bees Escape, Math Runner, Save The Dog, Helicopter Simulator 3D, Words Matching, Numberly, Thunder-Circuit.

For teachers, see teacher guide for pre-cache workflow. For parents, best for kids under 8 for Everyone set under 2MB.
