What “offline” actually means on a browser games site

Every games site says “play offline”. Half mean “we have a downloadable .exe”, other half mean “once loaded, it keeps working”. We mean the second, and we should be honest about limits.

The two layers: page cache and game logic

Layer 1 — Page cache (service worker): When you visit offlinegames.art, a small script `sw.js` installs. It caches `index.html`, `styles.css`, `catalog.js`, and the game files you opened. Next time you visit, even with flaky internet, the browser serves cached copies first, then checks network in background. That's why vault opens fast on second visit.

Layer 2 — Game logic: Each cartridge is HTML + JS + images bundled in `games/` folder. For Sudoku, puzzle generator runs in your tab, not on our server. For 2048, merge logic is local. So after initial download, no fetch needed. That's why airplane mode works after load.

What we cache and what we don't

We cache:

  • Shell: HTML, CSS, JS, icons, fonts (Google Fonts cached by browser)
  • Game builds you opened: e.g., `games/chess-3d.html`, `games/2048/` folder
  • Catalog: `catalog.js` (list of games)

We don't cache:

  • AdSense scripts — they always try network, fail offline, but don't block game
  • Google Fonts first load — after first load, browser caches them anyway
  • Games you never opened — to save storage, we don't pre-cache every game (would be ~30MB). We cache on demand.

Storage used: typically 5-15MB depending how many games you opened. You can clear via browser → Site settings → Clear storage.

Honest limits

First visit needs internet. You cannot type offlinegames.art with no signal and expect it to work. Service worker installs only after first load.

New games need internet once. If we add Color Clash today and you are offline, you won't see it until you go online and refresh. Our `catalog.js` is fetched with `cache: no-store` to avoid week-old cache, so refresh gets new list, but needs network.

High scores are local. We store favorites and high scores in `localStorage` in your browser, never on server. Offline, they still work. If you clear browser data, they disappear. We don't have cloud sync, which is actually better for privacy.

iOS Safari is weaker. Safari evicts service worker cache more aggressively than Chrome. On iPhone, if you don't visit for 7 days, cache may be cleared. Still, game logic itself (once loaded) keeps working in that tab even if cache cleared later.

Why we don't promise “100% offline”

Some sites claim 100% offline but still load ads, analytics, and fonts from third parties that fail offline and break layout. We keep third-party requests to AdSense and Fonts only, and we load them async so they don't block game. If they fail offline, game still runs, just no ads.

We also don't use heavy frameworks. No React, no bundler. Less code = less to cache, faster to load, less to break offline.

How to make vault work best offline

  1. On WiFi, open offlinegames.art, let it load.
  2. Open each game you want for 3 seconds, then close. This caches its build.
  3. Go offline (airplane mode), refresh vault — it should still open from cache.
  4. Play. Scores save locally.

If a game shows spinner offline, tell us via Contact — means it tries to fetch mid-game and we should fix.

Service worker lifecycle — simple version

Service worker has three phases: install, activate, fetch. On first visit, browser downloads sw.js and installs. During install, it caches shell files. On activate, it deletes old caches. On fetch, it intercepts requests: if request is for a cached game file, it serves from cache first, then updates cache in background (stale-while-revalidate). That's why second visit is instant.

We use cache-first for game builds, network-first for catalog.js. Why? Game builds rarely change, so cache-first is fast. Catalog changes when we add new game, so network-first ensures you see new games quickly, but falls back to cache if offline.

It also keeps the site readable when JavaScript does not run. Every game page ships its description, controls, how-to and FAQ in the HTML itself rather than injecting them afterwards, so the text is there for a screen reader, a text browser or a slow connection that never finishes loading the scripts.

Privacy and offline

Because high scores stay in localStorage, we never see them. No account, no tracking of which games you play offline. AdSense only sees page views when online. Offline play generates no ad impressions, which is honest — we don't fake impressions offline. When you go online again, next page view shows ads normally.

We also don't use fingerprinting. No canvas fingerprint, no third-party trackers besides Google. Our privacy page explains this, which AdSense reviewers check.
