Publish The Game

  1. Upload this folder's contents to https://offlinegames.art/numberly/. Keep the relative file names together.
  2. Open index.html. You can also open it directly from your computer for basic play. HTTPS or localhost is needed for service workers and portrait/fullscreen APIs.
  3. Serve .js as text/javascript and .css as text/css. Your host normally does this automatically.
  4. If you use a different URL, update the canonical and sharing URLs in index.html and your website's sitemap.
  5. For future updates, bump VERSION in resources.js so the service worker installs a fresh offline cache.

Preview-only files: The surrounding development workspace still has the React/Vite entry and configuration required by its preview environment, including src/App.tsx and package.json. Do not upload that scaffold. Upload only this standalone folder, which contains exclusively .html, .css, and .js files.

Ads And Required URLs

The ad client is ca-pub-4203857211510947 and the web banner slot is 7417753724. Interstitials are requested after every two completed rounds, with a two-minute cooldown and provider frequency limits. Ads are never simulated. Bonus gems are awarded only from the provider's completed-view callback and at most once per round.

Persistent bottom banner: The dark ad area stays at the bottom during play, pause, and level transitions. The game scrolls in a separate area above it, so the board, controls, dialogs, and notifications do not sit beneath the banner. Preview and offline modes show clearly labeled placeholder text, never a simulated paid ad.

Live bottom ads use Google's official anchor format. The loader in ads.js sets data-overlays="collapsed-bottom", Google's documented option for regular bottom-only anchors on desktop and mobile. The normal banner slot remains in configuration for non-sticky placements; it is not forced into a sticky mobile container or requested alongside the anchor. Anchors use the publisher account rather than a slot ID.

Publish index.html directly as the game page, not inside another site's iframe, for Auto ads eligibility. Confirm the site is approved in AdSense and review Ads > By site > Edit > Overlay formats > Anchor ads. Use the hosting site's required consent configuration before loading Google ads. The dock remains visible, but uninterrupted live inventory, autoplay video, or a new ad every few seconds cannot be guaranteed. There are no timer-driven banner refreshes and no automatic re-requests on restart or level changes. Google's creative controls any animation; the game does not fabricate playback. See Google's bottom-anchor documentation and ad placement policies.

Ads request live inventory only on offlinegames.art or its subdomains. The domain and account need Google approval and H5 Games Ads access. Ads may be unavailable. Use your website's Google-certified CMP wherever legally required; an informational game dialog does not replace consent collection.

Important: Google's authorized-seller endpoint must still be named /ads.txt. Renaming it to ads.html would break its purpose. No physical TXT file is included here. Add this line to your site's existing root ads.txt, or use a server route returning this plain-text content:

The optional server.js provides that URL dynamically from JavaScript without a TXT file. Do not overwrite an existing website's seller list. A browser service worker alone cannot provide ads.txt to Google's crawler.

Opening the game in a phone browser uses web ads. Native AdMob requires an actual app wrapper with a configured Google Mobile Ads SDK, app IDs, web-view integration, and consent handling. The native interstitial ID supplied was ca-app-pub-4203857211510947/3025427580, and the native banner ID was ca-app-pub-4203857211510947/8086182570. They are not web ad slots and cannot be activated by changing a file extension.

Offline And Portrait Mode

The game caches its HTML, CSS, and JavaScript after the first successful online visit. The PWA manifest is generated by the service worker; icons are drawn and cached from JavaScript. This avoids physical JSON, WEBMANIFEST, SVG, and PNG files. Installability still depends on your browser and its service-worker support.

The original fonts are optional CDN resources referenced from CSS. If the CDN is unreachable, system fonts are used. Music, effects, puzzles, and game logic work without external libraries. Ads need an internet connection.

Portrait fullscreen is requested on the phone's start gesture. The browser and OS can refuse rotation locking, especially on iOS Safari. The responsive landscape fallback remains available. A web game cannot force the device's orientation against all OS and browser restrictions.

Progress And Game Rules

The original numberly.progress.v1 storage key is preserved, so gems, completed levels, preferences, and local high scores remain available on the same browser origin. Moving to another domain or port, clearing browser data, or blocking storage affects access to saves.

Connect all numbers in order. Reach the final number to win; empty squares are allowed. All 200 generated puzzles keep a valid reference solution. Undo is free, hints cost 5 gems, and timed mode adds a countdown and 20% score bonus.

Local Server And Checks

The optional Node.js server uses built-in modules only. No packages are required.

node server.js

Open http://localhost:8080/. To run the pure JavaScript regression checks with Node.js instead of the browser:

node tests.js

The checks replay all 200 solutions, validate shorter paths, checkpoint ordering, backtracking, boundaries, and pause/resume timing. The separate browser smoke checks exercise real buttons and pointer input. Live ads, browser installation, orientation locking, and real-device frame rates need testing in their actual environments.
